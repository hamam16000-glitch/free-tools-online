UUID v4 Explained: Format, Uses and Safety

A UUID (Universally Unique Identifier) is a 128-bit identifier commonly used to distinguish records, objects and resources in software systems. UUID version 4 uses random values rather than sequential numbering.

Understanding the UUID v4 Format

A typical UUID contains 32 hexadecimal digits displayed in five groups separated by hyphens. The group lengths are 8-4-4-4-12.

For example: 

3f178f75-19d3-4a25-8e3a-b7974c978850

In a UUID v4, the first hexadecimal character of the third group is 4. The first character of the fourth group is 8, 9, a or b. These positions identify the UUID version and its standard variant.

A UUID v4 contains 122 random bits. The remaining six bits identify its version and variant.

Practical Uses for UUID Identifiers

Database Record Identification

Developers can use UUIDs as identifiers for database records. They are especially useful when identifiers must be created across different applications or systems.

A database should still enforce uniqueness where required. Random generation makes collisions extremely unlikely, but it does not mathematically guarantee uniqueness.

Testing APIs and Applications

A developer testing an API may need several different record identifiers. The Generate 5 UUIDs option provides example identifiers that can be copied into test data.

Distributed Applications

UUIDs can help independently operating systems create identifiers without asking one central service to allocate every ID.

Whether UUIDs are appropriate depends on the application's storage, indexing and performance requirements.

UUID vs GUID: What Is the Difference?

UUID means Universally Unique Identifier. GUID means Globally Unique Identifier, a term commonly associated with Microsoft technologies.

The terms are often used interchangeably when referring to identifiers with the standard 128-bit UUID structure.

UUID v4 vs UUID v7

UUID v4 is based on random values. UUID v7 includes a timestamp component, which can make it useful when identifiers benefit from time-oriented ordering.

This page generates UUID v4 only. It does not generate UUID v7 or other UUID versions.

Important UUID Limitations

  • UUID v4 identifiers are not guaranteed to be globally unique.
  • A UUID is an identifier, not a password or a substitute for authorization checks.
  • Random UUID v4 values do not provide creation-time ordering.
  • A UUID does not automatically prevent duplicate records in a database.
  • If secure browser randomness is unavailable, the generator reports an error rather than using an insecure random-number fallback.

UUID Privacy and Browser Security

UUID values are generated locally using browser cryptographic APIs. The generator does not need to submit generated identifiers to an external UUID-generation service.

The browser must support secure randomness. Modern browsers generally provide the required functionality in secure contexts.

Can two UUID v4 values be identical?

Yes, theoretically. UUID v4 has an extremely large space of possible random identifiers, making accidental collisions unlikely when generated correctly.

Applications requiring guaranteed record-level uniqueness should still use appropriate database constraints.

Can I use a UUID as a password?

A UUID should not replace a properly generated password or authentication system. Identifiers and security credentials serve different purposes.

Does UUID v4 contain a timestamp?

No. UUID v4 uses random data and does not encode a creation timestamp.

What happens if secure randomness is unavailable?
